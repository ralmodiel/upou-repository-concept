# Handoff: UPOU Repository concept (all-frontend POC)

## What is built
- A static React/Vite site (`web/`) that replaces browsing and search of repository.upou.edu.ph for 785 harvested items: browse by faculty/collection/type/tag, faceted search (BM25 over title, abstract and AI summaries, plus optional semantic vectors), item reader with AI summaries and citations (APA/MLA/Chicago/BibTeX/RIS), lists, maps (3D), advanced search, FAQ matching, offline service worker, consent-gated storage and model download.
- Everything runs in the browser. No server, no accounts, no analytics. Thesis full text is NOT shipped (see `docs/hosting.md`); search cards show abstract or AI-summary excerpts and link to the official record.
- 50 improvement rounds are logged one line each in `docs/rounds.md`; their checks live in `web/scripts/rounds.mjs` (`node scripts/rounds.mjs [n...]`, needs `vite preview --port 4195`).
- Speed (rounds 41-50): articles.json holds abstracts cut to 400 chars, the full abstracts and the 1/2-page summaries load after first paint (`texts.json`); `vecs.bin` is int8 (3.8 MB, loaded only after the model opt-in); lexical worker only before opt-in; index data is stale-while-revalidate; hybrid ranking is RRF with vector weight 0.35 and k 10.

## Rebuild
- Site, author's machine (has the adviser plaintext): `cd web && npm ci && ADV_USER=.. ADV_PASS=.. npm run build` (output `web/dist`, includes `read/<id>/` pages, sitemap, `sw.js`). Preview: `npx vite preview --port 4195`.
- Site, any fresh clone and CI (public repo, ciphertext only): `cd web && npm ci --ignore-scripts && npm run build:ci` builds from the committed snapshot `web/sealed/` with no credentials. After changing adviser data, faculty files, articles.json or faqs.json, reseal on the author's machine: `ADV_USER=.. ADV_PASS=.. node scripts/seal-snapshot.mjs`, then commit `web/sealed` (docs/access.md).
- Data (repo root Python, outputs in `web/public/index/`; articles.json, faqs.json and the adviser files are git-ignored and reach git only through `web/sealed`): `harvest.py` -> `fetch_pdfs.py` -> `chunk.py` -> `cd web && npm run index` (`build-index.mjs` embeddings, about 22 min, then `scripts/quantize-vecs.mjs` makes vecs.bin int8) and `passages.py` -> `summarize.py`, `faq.py`/`faq2.py`, `categorize.py` (local LLM) -> `assemble.py` -> `related.py` -> `assemble.py` again. `tag_items.py` (local LLM keyword tags, resumable, one worker, about 2.5 h for 785 items on the shared GPU) -> `tags_build.py` (no LLM: normalise, ground, merge, sub-topics from `subtopics_def.py`, categories for uncategorised items) -> `assemble.py` -> `tags_check.py` (verdict). **Re-run `tag_items.py` (it only tags new ids), `tags_build.py` and `assemble.py` whenever items change.** The root `*.py` pipeline scripts are git-ignored (local-only, kept on disk); `data/` too. `norm_authors.py` writes author aliases; `eval_set.py` rebuilds the search eval set. `data/` is git-ignored (PDFs, OCR, chunks, summaries).
- Do not re-run `build-index.mjs` unless chunks change; if only the quantised file was lost, rebuild from the float copy or re-embed.

## Auto tags and sub-topics (round 51)
- `subjects` = repository subjects merged with AI keyword tags; `autoTags` lists the AI ones (UI labels them with the AI badge); `subtopics` (33 AI sub-topics, 1-3 per item) are grouped under the top-level categories on /topics, have /sub/<slug> pages, type-ahead and Advanced facets. Tags do not feed BM25 (no index rebuild needed).

## Advisers and committee search (round 52)
- Page `/advisers` (lazy chunk) and `/adviser/<slug>`: topic input (categories, sub-topics, tags, free text, max 6) -> ranked people by per-topic score (word match always; meaning match only after the opt-in model is ready, AI-labelled), coverage bonus, greedy set-cover panel of 3 or 4 (user chooses), coverage matrix, copyable plain text. Tabs per candidate topic (add/rename/duplicate/reorder/delete, arrow keys) are stored only through `pref` (kept in memory unless the visitor consented). Thesis topic discovery (narrower topics, pairs, AI-labelled gaps, nearest theses). Maps: selected node -> "Add to committee search" (shared store `committee.js`).
- Badges: "No advisee in <LASTYEAR>" (LASTYEAR = max item year in the data) and "Has not advised in this repository". Based only on repository theses, not on availability. Advisers are shown as names only.
- Data: `advisers.jsonl` + `adviser-aliases.json` -> `assemble.py` adds `advisers` to articles.json -> `people.py` writes `web/public/index/people.json` and `people.bin` (int8 mean vectors, loaded only with the model). Refresh after OCR finishes: `advisers.py` -> `adviser_alias.py` -> `assemble.py` -> `people.py` -> `adviser_check.py`.
- Startup budget (round 53): the AI `half` summaries no longer ride in the startup articles.json; `seo.mjs` writes them to `index/half.json` (keyed by id, loaded with texts.json after first paint, not precached). A full `assemble.py` with 353 summaries gives startup 469 KB gz (budget 500). The late files grow with the summary count, so budget.mjs allows texts.json 1600 KB and the precache 1700 KB gz. The committed articles.json is still the older partial one: `summary-audit.mjs` fails on invented numbers in the AI summaries of both versions, so regenerate only after the summaries are reviewed.
- Gates: `adviser_check.py` (grounding, aliases, slugs, people index, held-out hit@3, multi-topic coverage, discovery) and rounds.mjs 52 (22 UI checks).
- Round 54 (advisers): privacy/no-submission assurance on /advisers, /adviser/*, /maps/adviser/* (AdviserPrivacy.jsx banner, "How do we know?", live Network activity, counter "Requests carrying your text" backed by netwatch.js wrappers of fetch/XHR/sendBeacon/WebSocket; worker model downloads are not visible to it). Writeups UI (Writeup.jsx: half/one/two, Copy, Print, ai/human + reviewed labels, absent state) reads index/profiles/<slug>.json lazily; generate with `adviser_profiles.py` then `--publish` (fact-sheet cap now 24000 chars, tail-drops oldest items). Maps Adviser seed (/maps/adviser/<slug>, IJODeL nodes with external link, sub-topic nodes, same-topic advisers, status badge, back link, "Also an adviser" on Author seeds). New faculty: BM25 over expertise text (scoring.js source `exp`, weights of other sources unchanged, held-out hit@3 unchanged 0.47 / sub-topic 0.6 / advisees-only 1.0); status `external` badged "External" and excluded from panels with former unless the include toggle. ALL adviser data loading goes through web/src/adviserData.js (loadPeople, loadVecs, loadProfile, loadIjSummaries): put decryption there in the login phase.
- Not built yet: generated writeups (`adviser_profiles.py` ungenerated, GPU busy).

## Access gate (round 55)
Adviser data is AES-256-GCM encrypted at build time and opened by a browser-side login (PBKDF2 against public `k.json`, key in memory only, Lock button). Details, the sealed snapshot, rotation and LIMITS: `docs/access.md`. `npm run build` REQUIRES `ADV_USER`/`ADV_PASS` inline (fails clearly otherwise); `npm run build:ci` (CI) needs none; `npm run dev` stays plaintext and open. Adviser names are no longer in the shipped `articles.json` (encrypted id-to-names map). Browser gates sign in via `scripts/adv-test.mjs` with creds from env; static gate `scripts/access-check.mjs`. adviser_check.py and faculty_check.mjs read the plaintext sources in `public/` and need no login. The repository is public: the plaintext lives only on the author's machine (git-ignored), git holds ciphertext (`web/sealed`).

## Faculty folder, IJODeL and evidence-mix scoring (round 53)
- `web/public/faculty/` (git-ignored except README.md and the schema example; input only, sealed into the encrypted set; README.md documents the schema): one JSON file per person to correct names (surname change `former_names`, `title`, `aliases`, `not_same_as`), set status (`active|new|former|external`), expertise, own works, IJODeL overrides, international overrides, writeups (AI or human, reviewed flag). Folder wins over `data/adviser-aliases.json`. `example: true` files are validated but left out of the site.
- Build: `root people.py` (git-ignored) writes the thesis-derived base to `web/data/people.base.json` + `people.base.bin`; `web/scripts/people-merge.mjs` (run by `npm run build` and `seal-snapshot.mjs`, committed; a fresh clone has no plaintext and builds with `build:ci`) merges the folder and the IJODeL snapshot into `public/index/people.json`, `people.bin` and `public/index/ijodel/<slug>.json` (AI half-page summaries of matched IJODeL articles) and stops with a clear message on a schema error. Old slugs are kept in `os` and redirect (`#/adviser/<old>`). People merged by hand get the mean of their vector rows; a split-off or new person has a zero row (word match only until `people.py` is extended).
- IJODeL: root `ijodel_snapshot.py` (git-ignored) writes `public/faculty/ijodel-articles.json` (id, title, authors, year, url, subjects, categories) and `web/data/ijodel-half.json` from the sibling ijodel-rag project. Names match on surname + first name (initial allowed), accents and Dela Pena variants ignored; a name that fits two people is not merged; `ijodel_authors` forces, `ijodel_exclude` removes. Links are exactly `https://ijodel.upou.edu.ph/ijodel/article/view/<digits>`, `rel="noopener noreferrer"`, labelled "From IJODeL", no PDF links.
- International: root `intl_flags.py` (git-ignored) writes `public/index/international.json` (rule: repository Scholarly Article with an external publisher, a non-Zenodo DOI or a venue-like citation; IJODeL articles are international by definition). Overrides per person in the faculty file.
- Scoring constants live in ONE file, `web/src/scoring.js`: per topic each source contributes `W * quality` (advisees 1, own 1.2, international 1.6, IJODeL 1.4), quality = half the best matching item + half the mean of the top 3 (each match 0..1 x mild recency), so people rank by quality of match, not by how many theses they advised (items past the third add nothing); chair score = match x (1 + 1.5 x international share); track record (log of recency-decayed advised-thesis count, tau 5 data years) and thesis count only break exact ties. Chair: has advised, not `new`, not `former` unless "Include former faculty" is ticked. Evidence-mix bar and "Chair because" text on the cards.
- Gates: `node scripts/faculty_check.mjs`, `python adviser_check.py` (weight order, chair, badges), rounds.mjs 53.

## Human tasks
- UPOU operator and Data Protection Officer (DPO) details in the privacy notice are placeholders marked `[..]` (asserted by round 37); UPOU must supply them.
- Human review of all AI content: summaries, FAQs, categories, related lists (the grounding script only checks that numbers occur in the source; it does not judge truth).
- Set the `SITE_URL` repository variable (canonical URLs, sitemap, social tags); the default host in `seo.mjs` is unverified.
- Copyright decision: the owner has not answered the question in `docs/hosting.md`; passages stay unpublished until UPOU gives written permission. Dropping `vecs.bin` is the fallback if they object to derived vectors.
- Real-device checks: low-end Android, iOS Safari (service worker, IndexedDB, 3D map), slow 3G; lab numbers here are Chromium at 4x CPU only.
- Hosting headers: GitHub Pages cannot send headers, so CSP is a meta tag; on the final UPOU host set the headers in `README.md` / `dist/_headers` (CSP with `frame-ancestors`, nosniff, referrer policy, HSTS, permissions policy).
